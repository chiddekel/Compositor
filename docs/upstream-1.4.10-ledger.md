## What the Linux layer needed

- **Camera HEIF** (`70b3e14`): upstream now lists `.heif` beside `.heic` in `UTType.importableImages`, the import type
  check and the drop list. Its compiled-as-is code relies on three Apple behaviours the compat layer lacked:
  - `UTType(filenameExtension: "hif")` resolves to `public.heif` (the compat table only knew `heif`). Like macOS,
    `public.heic` and `public.heif` are now siblings under `public.heif-standard`, both still images.
  - `CGImageSourceGetType` types a container by its major brand: HEVC brands (`heic`, `heix`, `hevc`, `hevx`, ...)
    are `public.heic`; the generic MIAF brands cameras write (`mif1`, `msf1`) are `public.heif`. The libheif decoder
    in `host/QtImageIO.cpp` and the header sniff in `Sources/Compat/ImageIO/ImageCodec.swift` used to report every
    container as `public.heic` (sniff only recognised `ftypheic`).
  - The Qt import filter (`host/QtPlatformServices.h`) offers `*.hif`; the desktop entry (Flatpak and
    `run-compositor.sh --install-desktop`) declares `image/heic` and `image/heif`, as `Config/Info.plist` does.
- **App icon** (`ce5ea67`): Linux reads `AppIcon.appiconset` directly at install/package time, so the new icon needs no copy.
- **Version** (`eb1fda7`): `scripts/sync-version.sh` regenerates `host/AppVersion.h` (1.4.10, build 45).
- **Update feed** (`a1bd74c`): Sparkle `appcast.xml`, Mac only; Linux updates through Flatpak.
