## What was missing on Linux, and the fix

1. `Sources/Compat/UniformTypeIdentifiers/UTType.swift`: `public.heif` knew only `heif`. Added `hif`, and the macOS
   hierarchy `public.heic`/`public.heif` -> `public.heif-standard` -> `public.image`.
2. `Sources/Compat/ImageIO/ImageCodec.swift` `sniff`: recognised only `ftypheic`. Now HEVC brands
   (`heic heix hevc hevx heim heis`) -> `public.heic`, MIAF brands (`mif1 msf1`) -> `public.heif`; AVIF stays unclaimed.
3. `host/QtImageIO.cpp` libheif decode reported every non-AVIF container as `public.heic`; `mif1`/`msf1` now report
   `public.heif`, as `CGImageSourceGetType` does.
4. `host/QtPlatformServices.h` import filter: `*.hif` added.
5. Desktop entries (`flatpak/com.compositor.Client.desktop`, `scripts/run-compositor.sh --install-desktop`):
   `image/heic;image/heif` added, matching `Config/Info.plist` document types.
6. `host/AppVersion.h` regenerated by `scripts/sync-version.sh` (1.4.10 / 45).
7. Gate: `linux/upstream-parity.json` ledger range `39d1257..a1bd74c`; `scripts/check-upstream-clean.sh` checks the
   new ledger and pins the post-1.4.9 ledger to its own range.
